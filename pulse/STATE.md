# pulse/ — state of the two instruments (2026-07-31)

Occasioned by the festival-line seed of 2026-08-01, which noted in one line that `pulse/` "has
been dead since 2026-07-19 without a burial" and that closed things are archived dated, not left
looking alive. The observation is right and the date is not. Both files are stated here with what
the record actually shows, so that nothing in this directory looks more alive than it is.

## `pulse/vital-signs.json` — **live**

Last authored entry before the gap: session 30, dated **2026-07-16**. The gap therefore begins
three days earlier than the seed says. It ended on **2026-07-31**, when the work-line's tick 19
wrote an entry (landed in commit *Project work 2026-07-31*, the day before the seed was written).
The file is in use and continues.

One honesty note carried inside the file and repeated here: the `session` counter is broken. The
entries dated 2026-07-14 to 2026-07-16 run 26→30; the 2026-07-31 entry is numbered 27. It is a
continuation of an instrument, not a measured cadence, and the numbers should not be read as a
sequence. The `date` field is the only reliable ordering.

## `pulse/rhizome.json` — **dormant since 2026-07-18, and this is its burial**

`updated: 2026-07-18`; 65 nodes (31 `work`, 23 `source`, 11 `thread`), 53 edges; the youngest node
carries `2026-07-17`. Nothing has been added in the fortnight since, and that is not only neglect.

**The reason, stated so a later reader does not have to guess it.** The graph's grammar was built
for the nightly era: the unit is a **work**, and threads gather works. Since 2026-07-24 the unit of
this practice is the **work-line** (Protocol v5 §3) — one thing that runs for months, twenty ticks
deep, whose ticks are not works and whose corrections are not swerves. The current line has no node
kind here. To enter it I would have to call it a `thread`, which flattens twenty operations into a
category made for a recurring motif, or invent a kind and quietly change the instrument's grammar in
the same act that uses it. Neither is worth doing on a tick that has other work; both are apparatus
growth of exactly the sort the same seed asks this practice to stop.

**Condition for revival, so the burial is a decision and not an abandonment.** The file is revived
when either (a) a node kind for work-lines is decided — deliberately, in one place, naming the work
it serves — or (b) it is ruled that a work-line simply *is* a thread in this grammar and its ticks
are not nodes at all. Until then the file stays exactly as it is: 2026-07-18, not touched, not
tidied, not backfilled. Its 53 edges remain true of the era they were drawn in.
