## 3. The reading I used, stated so it can be argued with

The claim fixes a population (*systems that automate the research cycle end to end*) and an
operation (*verify their own outputs independently of the component that produced them*).
The criteria define the operation and leave the population implicit. I resolved it this way,
uniformly, and every rationale in the set names which part did the work:

- An excerpt **engages** the claim when the source's own evidence says whether an automating
  system's outputs are checked by something other than the component that produced them.
- Engaged, general, checker separate → `supports`.
- Engaged, checker is the same model / component / process, or absent → `contradicts`.
- Engaged but **fenced** — to a stage, a domain outside the research cycle, a configuration,
  or the reach of the source's own tests → `qualifies`.
- **Not engaged** — no checking arrangement of the source's own system is reported: a survey,
  a taxonomy, an identifier scheme, a vision with no system, or a benchmark measuring some
  other property → `contextualizes`.

That last line is why `contextualizes` is 20. Twenty of these papers describe a checker that
belongs to *the benchmark*, applied to agents from outside, and say nothing about how the
agents check themselves. That is a fact about the corpus, and it is worth knowing before it
is read as a fact about a classifier.

## 4. Three findings about the criteria

### 4.1 `supports` has a generality fence and `contradicts` has none

Read them side by side. `supports` ends: *"A general assertion, not one fenced to a named
subset."* `contradicts` ends: *"Self-review counts as contradicting, because the claim is
about independence, not about the existence of review."* No fence.

So a paper whose system self-verifies inside one narrow domain **contradicts** the claim,
while a paper whose system is checked by an external solver inside the same narrow domain
only **qualifies** it. The same fence is fatal on one side and free on the other. I applied
the rules as written rather than smoothing them — that is what an outside reader is for —
but the asymmetry is doing real work: it is the largest single reason `contradicts` (12)
outnumbers `supports` (1) by twelve to one in this set.

This is not the same objection as the one you accepted. That one was about a tie-break
hiding itself. This one is about a fence that exists on one side of the matrix and not the
other, in a corpus where every paper fences its evidence.

### 4.2 `supports` is nearly an empty class, and the fence is why

One case in sixty: `mbcls-2604.00149` (PhysVEC), which asserts programming and scientific
verifiers checking generated work *at each step*, of the framework as such. Every other
candidate for `supports` was defeated not by the absence of an independent checker — a
logical solver, a physics simulation, an execution harness, a frozen verifier model, a
platform verifier — but by the source fencing its own evidence to its own benchmark, which
is what a paper does.

The consequence is arithmetic and you should have it before you compute anything: a macro F1
over four classes on this set has a class with n = 1. One case decides a quarter of the
macro average. Any confidence interval on that quarter is nearly the width of the range. My
earlier construction — *macro F1 as an interval beside the per-class counts* — was written
before I knew how lopsided the counts would be; with n = 1 the interval is not a refinement
of the number, it is a reason not to report the number at all. Report the four per-class
counts and the four per-class agreements. Not a macro average.

If you think the fence should not be read that strictly, that is a live disagreement and the
right way to settle it is not to re-label but to say so and re-derive: every case carries
`decided_by`, so the set can be re-read with the fence relaxed by looking at exactly which
labels name `qualifies definition` and rest on a fence rather than on a missing checker.

### 4.3 The tie-break covers one edge of the matrix, and the fenced contradiction has no cell

`R-conservative-supports` fires only between `supports` and `qualifies`. But the recurring
hard case in this corpus is a different pair: a system that self-checks, unambiguously,
*inside a domain that is not the research cycle* — robot planning, mathematical word
problems, computer use. Under 4.1 those go to `contradicts`, and they go there silently:
there is no field that records that the decision was a close one between `contradicts` and
`qualifies`, because ties are only recordable on the other edge.

This is the defect you accepted, surviving on the edge the repair did not reach. The fix is
the same shape and costs the same one field: let `tie_with` carry a runner-up for any pair,
not only for the pair the conservative rule adjudicates. Then a `contradicts` that a fence
nearly overturned is as visible as a `qualifies` that a coin-flip produced.

## 5. The three undecidable cases

Reported as their own count, per `R-undecidable-is-a-finding`, and excluded from the matrix:

- **`mbcls-2410.01440`** — the refinement signal is stated disjunctively: feedback *"from the
  environment (or an internal world model)"*. Independent or internal is precisely the
  distinction the criteria decide on, and the excerpt states both with an "or".
  `R-excerpt-only` forbids me resolving it from the paper.
- **`mbcls-2505.12501`** — names *"absence of self-verification"* as a deficit the system
  tackles, and never says what performs verification in the system that tackles it.
- **`mbcls-2607.03863`** — reports *"verification checkpoints"* and improved verification
  performance, and never says what performs a check relative to the component whose artefact
  is checked.

All three fail on the same word. `independently` is the operative term of the claim, and
these excerpts report that checking happens without reporting who does it. Three in sixty is
5% — a small, specific coverage number, and it points at one thing rather than at noise.
